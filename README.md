# tp129 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

档案一多，可以把常看的地区分到几个自己取名的常用组里，按组切换查看；组内顺序支持手工上移下移，也可以整个组按偏移从小到大重排一遍。没有归组的档案统一摆在「未分组」默认组里，任何操作都不会让档案凭空消失。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5129>

端口固定为 `5129`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、标准偏移、是否实行夏令时、夏令时偏移、切换规则、生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名与偏移；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及生效年份填上
3. 换算台选好日期、时刻与来源时区，点换算一遍，页面列出每个已登记时区的当地日期、当地时刻、星期、与来源是否同一天、偏移以及跟来源时区差多少
4. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 常用分组怎么用

1. 档案区顶部是分组标签：最前面是「未分组」默认组，后面是各自取了名的常用组，每个标签上都写着组内眼下有几条；点标签按组切换查看
2. 点「＋ 新建分组」取名建组，组名不能为空、不能重复，最长 20 个字符；建好的组可以重命名，也可以删除
3. 每条档案那一行有「移到…」下拉，选中目标组即完成跨组移动，页面提示会写清把哪条档案从哪个组移到了哪个组；一条档案任何时候只属于一个组
4. 在常用组里，每条档案可以上移、下移调整组内顺序；到了最前或最后再继续往边上移会被拒绝。未分组按偏移自动排列，不支持手工调序
5. 组管理条上的「按偏移重排」会把整个组按标准偏移从小到大重排一遍，重排会盖掉组内原来的手工顺序，点之前页面会先弹确认提示这件事
6. 单个组最多容纳 50 条档案，超出时当场拒绝，并指出是哪个组已经满了
7. 删除分组不会删掉档案：组里的档案全部回到「未分组」；删除单条档案时它也会自动从所在组摘除
8. 换算台的来源时区下拉始终列出全部档案，不受当前正在查看哪个分组影响

## 换算口径

- 换算按登记的标准偏移进行：先把输入的当地时刻减去来源时区的标准偏移得到基准时刻，再逐个时区加上各自的偏移
- 每个时区的当地日期与时刻都由基准时刻加上该时区的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 与来源时区的时差按两边偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 结果按偏移从小到大排列，来源时区那一条在页面上会标出来
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 标准偏移与夏令时偏移都按整数分钟登记，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数（例如东五区半写 330、加德满都写 345）
- 实行夏令时的档案必须填夏令时偏移，且要比标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 生效年份填 1900 到 2100 之间；结束年份留空表示至今有效，已经停止实行夏令时的地区要把结束年份填上
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...], "groups": [...] }`。每个分组记录含 `id`、`name`、`zoneIds`（组内档案编号，即组内手工顺序）与时间戳；「未分组」默认组不落记录，内容按档案表实时算出。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

整理数据时分组同样做容错：组名去首尾空白，空名与重名的组只留第一条，同一条档案出现在多个组时只保留最先出现的一处（其余自动回到未分组），组内重复编号去重，引用了已删除档案的编号直接丢弃。

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时、关键词与 `groupId`（`default` 表示未分组）筛选 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案                               |
| PATCH  | /api/zones/:id   | 修改档案                                   |
| DELETE | /api/zones/:id   | 删除档案（同时从所有分组摘除）             |
| GET    | /api/groups      | 分组清单（默认组在最前，含各组条数与单组上限 50） |
| POST   | /api/groups      | 新建分组（名称非空、不重复、最长 20 字）   |
| PATCH  | /api/groups/:id  | 分组改名（默认组受保护，不可改）           |
| DELETE | /api/groups/:id  | 删除分组（组内档案全部回到未分组，不删档案） |
| POST   | /api/groups/assign | 把一条档案移到某组（含移回未分组），返回来源组与目标组名称 |
| POST   | /api/groups/order | 组内上移（`direction: "up"`）或下移（`"down"`） |
| POST   | /api/groups/sort | 整个组按偏移从小到大重排；必须带 `confirm: true`，表示已就「盖掉手工顺序」提示过用户 |
| POST   | /api/convert     | 把一个时刻换算到所有已登记的时区           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
